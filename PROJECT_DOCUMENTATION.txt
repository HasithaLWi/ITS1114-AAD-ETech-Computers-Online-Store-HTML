1. SYSTEM OVERVIEW & ARCHITECTURE
================================================================================

1.1 High-Level Architecture & Principles
--------------------------------------------------------------------------------
The ETech Computers Front-End Application is engineered as a zero-dependency,
high-performance Single Page Application (SPA) built using standard HTML5,
Tailwind CSS (v3 CDN configuration), Vanilla JavaScript (ES Modules), and CSS
Custom Properties.

The architecture emphasizes modularity, separation of concerns, strict state
persistence, and zero client build overhead. Business logic is organized into
Controllers, Data Models, Services, and Dynamic Page Renderers, interconnected
via an ES Module Window Bridge (`script.js`).

Primary Architectural Pillars:
- Modular Controller Layer: Discrete controllers manage storefront and administrative features.
- Single Source of Truth CSS System: Global variables in `src/css/variables.css` enforce branding, colors, spacing, and typography.
- Client-Side Mock Data Engine: Implements fully functional CRUD operations using browser `localStorage`.
- Backend Readiness: Formatted for direct drop-in integration with a Java Spring Boot REST API and MySQL database.

1.2 Single Page Application (SPA) Routing & Hash Navigation
--------------------------------------------------------------------------------
Routing is driven by URL hash fragments (`window.location.hash`) handled centrally
in `src/js/app/app.js`. When a hash change event fires, `handleRoute()` inspects
the URL, enforces route guards, toggles visibility on section elements
(`.page-section`), and executes page-specific lifecycle hooks.

Supported Routes & Viewports:
- `#home`: Main landing storefront, featuring hero 3D carousel, brand value props, and top featured products.
- `#shop`: Full product catalog with real-time multi-criteria filtering, search, pagination, and category chips.
- `#product?id=X` / `#product-details?id=X`: Dynamic hardware product specs, 5-image gallery, rating breakdown, and customer review submitting form.
- `#cart`: Interactive shopping cart drawer/table with real-time subtotal, tax calculation, and item quantity adjusters.
- `#checkout`: Multi-step checkout with distance-based shipping fee calculation, branch fulfillment selection, and order placement.
- `#login` / `#signup`: Authentication portal for login, registration, password visibility toggles, and role redirection.
- `#account`: Customer dashboard displaying profile metrics, editable user details, and order history with live status tags.
- `#admin` / `#administrator`: Full-screen staff management console (hidden storefront header/footer/chatbot during active session).
- `#about`: Corporate profile page displaying company history, branch network, and executive mission.
- `#privacy` / `#terms` / `#warranty` / `#policies`: Interactive legal policy portal with print action and section accordions.

Route Protection & Security Guards:
1. Protected Customer Routes (`#checkout`, `#account`):
   - Checked via `isLoggedIn()`.
   - Unauthenticated access redirects automatically to `#login?redirect=<target_route>`.
2. Protected Admin Console Routes (`#admin`, `#administrator`):
   - Checked via `isLoggedIn()` and role check (`user.role === 'ADMIN' || user.role === 'STAFF'`).
   - Unauthorized customers receive an "Access Denied" alert and are returned to `#home`.
3. Dynamic Shell Visibility:
   - When transitioning to `#admin`, the global header, store footer, and chatbot FAB are hidden (`classList.add('hidden')`) to provide a dedicated desktop workspace.

1.3 Module Binding & Global Window Bridge System (script.js)
--------------------------------------------------------------------------------
Because ES Modules maintain isolated module scope, inline HTML event attributes
(e.g., `onclick="addToCart(4)"` or `oninput="filterProductsTable()"`) cannot
access un-exported ES Module functions directly.

To bridge ES Modules with standard DOM event handlers without abandoning modular code:
- `script.js` imports every controller method, model accessor, and helper function.
- It executes `Object.assign(window, { ... })` upon load.
- This binds all necessary functions globally to the `window` object while keeping code modularly organized in separate `.js` files.

1.4 Client-Side State Engine & Persistence Strategy (LocalStorage)
--------------------------------------------------------------------------------
All data—including products, user accounts, active cart items, placed orders, branch details, stock health rules, taxonomy categories, and legal policies—is stored in browser `localStorage`.

Data Initialization Pattern:
1. When a model file loads (e.g., `src/js/models/data.js`), it checks if its corresponding key exists in `localStorage`.
2. If absent, it populates `localStorage` with initial default datasets (seeded hardware inventory, admin accounts, default branches).
3. Any mutation (e.g., updating stock, creating a product, placing an order) commits changes back to `localStorage` and triggers window events (`productsUpdated`, `cartUpdated`, `storage`) to sync UI state instantly across tabs.

2.1 Aesthetic Archetype & Design Philosophy
--------------------------------------------------------------------------------
Archetype: Modern Light Precision Hardware Storefront
The visual language is tailored for high-performance PC hardware retail and
enterprise procurement. It replaces noisy neon gaming gradients with a clean,
structured layout consisting of pure white card surfaces, soft slate-50 canvas backgrounds,
crisp 1px slate-200 borders, royal engineering blue action triggers, and high-contrast typography.

Core Pillars:
- Pure White Canvas & Soft Slate Hierarchy: Pristine white (`#ffffff`) surfaces paired with soft slate (`#f8fafc`) page backgrounds.
- Structural Geometry: Hardware-inspired border radius (`4px` to `8px`) without soft bubble corners.
- Engineering Blue Focus: Royal blue (`#2563eb`) guides primary calls to action, badges, and focal elements.
- Technical Typography: Dual-font system separating body copy from technical SKUs and pricing data.

2.2 CSS Variables & Design Tokens (src/css/variables.css)
--------------------------------------------------------------------------------
All design tokens are defined under `:root` in `src/css/variables.css` as the single source of truth.

3.1 Dynamic Header Navigation & Mobile Drawer (Auth UI Sync)
--------------------------------------------------------------------------------
Function: `updateHeaderAuthUI()` (in `src/js/app/app.js`)
- Checks `getCurrentUser()`.
- Unauthenticated User: Displays "Sign In" button leading to `#login`.
- Authenticated Customer: Displays user avatar pill (user's first initial, e.g. "H") and first name linked to `#account`.

3.2 Hero Section & 3D Layered New Arrivals Product Carousel Engine
--------------------------------------------------------------------------------
Function: `renderHomeNewArrivalsCarousel()` (in `src/js/app/app.js`)
- Pulls product array via `getNewArrivalProducts()` (products with `badge === 'New Arrival'` or newly added flag).
- Renders prev, current, and next cards in 3D depth stacked view.
- Provides interactive navigation arrows, numeric indicator (`current / total`), touch swipe listeners, and timer control (`startHeroCarouselAutoPlay()`, `pauseHeroCarousel()`).

3.3 Catalog Shop Logic & Multi-Parametric Filter System
--------------------------------------------------------------------------------
Module: `src/js/controller/shop_controller.js`
Logic Flow:
1. State Management: Tracks search keyword, selected category filters (set/array), selected brand, price range filter (min/max), sorting option, and current pagination page.
2. Multi-Parametric Filter Chain (`getFilteredProducts()`):
   - Step 1: Category Filter - Matches product category against selected category tags.
   - Step 2: Search Filter - Performs case-insensitive matching on product name, description, category, and technical specs.
   - Step 3: Brand Filter - Filters products matching selected brand.
   - Step 4: Price Range Filter - Enforces min & max price bounds.
   - Step 5: Sorting:
     * `featured`: Default priority ordering.
     * `price-low`: Ascending price order.
     * `price-high`: Descending price order.
     * `newest`: Sorted by product ID / creation timestamp descending.
     * `rating`: Sorted by customer review rating average.
3. Pagination: Calculates total pages (`Math.ceil(total / itemsPerPage)`) and slices result array for current page view.

3.4 Product Details View, Image Gallery & Rating System
--------------------------------------------------------------------------------
Module: `src/js/controller/product-details_controller.js` & `src/js/models/rating_data.js`
Features:
- Dynamic 5-Image Gallery: Primary large preview image with 4 interactive thumbnail selectors (`changeMainImage(url)`).
- Stock Availability Badge: Dynamic calculation based on total warehouse stock across Colombo, Kandy, Galle, and Matara.
- Key Specifications Table: Renders dynamic key-value pairs (Processor, RAM, VRAM, Chipset, Socket, Power Draw).
- Customer Review & Star Rating:
  * Computes weighted average rating (1.0 to 5.0 stars).
  * Enforces verified buyer review submission (`submitProductReview()`).
  * Displays star breakdown bars (5-star down to 1-star counts).

3.5 Cart Logic & Checkout Engine
--------------------------------------------------------------------------------
Module: `src/js/controller/cart_controller.js`
Logic Flow:
1. `addToCart(productId, quantity)`:
   - Fetches product details.
   - Checks stock availability.
   - Adds item to `localStorage` key `etech_cart` or updates quantity if item exists.
   - Dispatches `cartUpdated` event and updates header cart badge counter (`updateCartBadge()`).
2. Cart Operations: `updateItemQuantity(productId, newQty)`, `removeItemFromCart(productId)`.
3. Financial Calculations:
   - Subtotal = Sum of `(item.price * item.quantity)`.
   - Tax = Subtotal * 0.00 (or configured tax rate).
   - Shipping Fee = Calculated dynamically based on shipping city distance from fulfillment branch.
   - Order Total = Subtotal + Shipping Fee.

3.6 Branch Selection & Shipping Fee Calculation Algorithm
--------------------------------------------------------------------------------
Module: `src/js/controller/branch_controller.js`
Features:
- Branch Network: Colombo HQ, Kandy Branch, Galle Branch, Matara Branch.
- Geographic Coordinates & Distance Matrix:
  Computes approximate distance in kilometers between customer delivery city and nearest branch.
- Shipping Fee Matrix:
  * Standard Delivery (< 15 km): Rs. 350
  * Regional Delivery (15 – 50 km): Rs. 750
  * Express Long-Distance (> 50 km): Rs. 1,250 + Rs. 15/km excess.
- Automated Fulfillment Branch Selection Algorithm (`autoSelectFulfillmentBranch(deliveryCity, orderItems)`):
  Iterates through branches to locate the nearest branch that has full stock available for all items in the cart.

3.7 User Authentication, Access Control & Roles
--------------------------------------------------------------------------------
Module: `src/js/controller/login_controller.js`
Roles & Permissions Matrix:
- `ADMIN`: Full access to storefront, product management, order updates, stock health restock/transfers, branch configuration, user management, analytics, taxonomy rules, and policy editing.
- `STAFF`: Access to storefront, product creation/editing, order status management, and stock monitoring. Restricted from deleting users or altering taxonomy rules.
- `CUSTOMER`: Access to storefront, shop catalog, cart, checkout, customer account portal, review submission, and order history tracking.

3.8 Customer Account Portal & Order History Tracking
--------------------------------------------------------------------------------
Function: `initAccountLogic()`, `renderUserOrderHistory()` (in `app.js`)
- Displays profile card (Avatar initial, Name, Username, Email, User ID, Registration date, Role).
- Renders customer order history cards with order ID (`#ETC-XXXXXX`), order status badge, date, total amount, dispatch hub, destination city, items grid, and payment verification badge.

4.3 Order Management Module & Order Lifecycle Tracking
--------------------------------------------------------------------------------
Module: `src/js/controller/order_management_controller.js`
Lifecycle Workflow:
1. `PENDING`: Order placed by customer; pending fulfillment verification.
2. `PROCESSING`: Items allocated in warehouse; packaging for courier dispatch.
3. `SHIPPED`: Order handed to courier with tracking number.
4. `DELIVERED`: Order confirmed delivered to customer.
5. `CANCELLED`: Order cancelled; warehouse stock restored automatically.

4.4 Stock Health & Inventory Alert Monitor
--------------------------------------------------------------------------------
Module: `src/js/controller/stock_health_controller.js`
Functionality:
- Multi-Branch Inventory Matrix: Displays branch breakdown (Colombo, Kandy, Galle, Matara) and total stock.
- Automated Alert Triggers:
  * Out of Stock Alert (Total stock = 0): Danger badge (`bg-rose-50`).
  * Low Stock Alert (Total stock <= reorder margin): Warning badge (`bg-amber-50`).
  * Optimal Stock (Total stock > reorder margin): Success badge (`bg-emerald-50`).
- Restock Modal Algorithm (`handleQuickRestockSubmit()`):
  Allows direct stock additions to specific warehouse locations.
- Inter-Branch Stock Transfer Algorithm (`handleStockTransferSubmit()`):
  Transfers inventory from a source branch (e.g., Colombo HQ) to a destination branch (e.g., Kandy Branch), verifying stock sufficiency before execution.

4.5 Branch Management Module
--------------------------------------------------------------------------------
Module: `src/js/controller/branch_management_controller.js`
- Manages branch profile, contact phone, manager name, address, coordinates, delivery radius, and operating hours.

4.6 User Account Management Module
--------------------------------------------------------------------------------
Module: `src/js/controller/user_management_controller.js`
- Displays registered users table, changes roles (`ADMIN`, `STAFF`, `CUSTOMER`), suspends/activates accounts, or removes users.

4.7 Taxonomy, Automated Badge System & Product Behavior Analytics
--------------------------------------------------------------------------------
Module: `src/js/controller/taxonomy_controller.js` & `src/js/models/taxonomy_data.js`
Features:
- Category Management: Create, edit, delete product categories with slug, icon, and parent relationship.
- Automated Product Badge Engine (`runAutoBadgeAssignment()`):
  Automatically assigns badges (`Best Seller`, `Trending`, `Hot Deal`, `Low Stock`) based on metric thresholds:
  * `Best Seller`: Total units sold >= threshold (e.g. 50 units).
  * `Trending`: View count within 7 days >= threshold.
  * `Hot Deal`: Discount percentage >= 15%.
  * `Low Stock`: Stock between 1 and 5.

4.8 Corporate Profile & Legal Policy Management Engine
--------------------------------------------------------------------------------
Module: `src/js/controller/policy_management_controller.js` & `src/js/models/policy-data.js`
- WYSIWYG section builder for Privacy Policy, Terms of Service, Warranty Guarantee, and Refund Policy.
- Editable corporate contact info (Hotline, Email, Tax Registration Number, HQ Address).

4.9 E-T AI Technical Advisor Chatbot Engine
--------------------------------------------------------------------------------
Module: `src/js/controller/chatbot_controller.js` & `src/js/models/et-training.js`
Features:
- Gemini API Integration: Connects to Google Gemini API for hardware advice and PC building recommendations.
- Context Training System (`ET_CONFIG`): Embedded system prompt training the AI as an expert hardware consultant for ETech Computers.
- Local Intelligent Fallback Engine: Provides instant responses for stock availability, store hours, shipping rates, and warranty policies when offline.
- Quick Suggestion Chips: Preset query buttons (e.g., "Build Gaming PC under 300k", "Check RTX 4080 Stock").

6. BACKEND API MIGRATION ROADMAP (SPRING BOOT + MYSQL)
================================================================================

6.1 Target Database Relational Schema Overview (DDL)
--------------------------------------------------------------------------------
To migrate from `localStorage` to a Spring Boot REST API:

1. `users` Table: `id` (BIGINT PK), `name`, `username`, `email`, `password_hash`, `role` (ENUM: ADMIN, STAFF, CUSTOMER), `created_at`.
2. `categories` Table: `id` (BIGINT PK), `name`, `slug`, `icon`, `parent_id` (FK).
3. `products` Table: `id` (BIGINT PK), `name`, `category_id` (FK), `brand`, `price` (DECIMAL), `original_price`, `reorder_margin`, `badge`, `main_image_url`, `description`, `warranty`, `created_at`.
4. `product_images` Table: `id` (BIGINT PK), `product_id` (FK), `image_url`, `display_order`.
5. `product_specs` Table: `id` (BIGINT PK), `product_id` (FK), `spec_key`, `spec_value`.
6. `branches` Table: `id` (VARCHAR PK), `name`, `city`, `address`, `phone`, `manager`, `latitude`, `longitude`.
7. `branch_inventory` Table: `id` (BIGINT PK), `branch_id` (FK), `product_id` (FK), `stock_quantity`.
8. `orders` Table: `order_id` (VARCHAR PK), `user_id` (FK), `customer_name`, `email`, `phone`, `address`, `city`, `fulfillment_branch_id` (FK), `subtotal`, `shipping_fee`, `total_amount`, `payment_method`, `status`, `created_at`.
9. `order_items` Table: `id` (BIGINT PK), `order_id` (FK), `product_id` (FK), `unit_price`, `quantity`.

6.2 Spring Boot REST API Endpoint Specifications
--------------------------------------------------------------------------------
- Product Endpoints:
  * `GET /api/v1/products` - Returns paginated, filtered hardware catalog.
  * `GET /api/v1/products/{id}` - Returns complete product details with images & specs.
  * `POST /api/v1/products` - Creates new product (Admin/Staff).
  * `PUT /api/v1/products/{id}` - Updates product specs and inventory (Admin/Staff).
  * `DELETE /api/v1/products/{id}` - Removes product (Admin).
- Inventory & Stock Endpoints:
  * `GET /api/v1/inventory/stock-health` - Stock alert status across all branches.
  * `POST /api/v1/inventory/restock` - Adds stock to branch inventory.
  * `POST /api/v1/inventory/transfer` - Inter-branch stock transfer.
- Order Endpoints:
  * `POST /api/v1/orders` - Places order, calculates branch allocation & shipping fee.
  * `GET /api/v1/orders/my-orders` - Fetches authenticated user's order history.
  * `GET /api/v1/orders` - Fetches all customer orders (Admin/Staff).
  * `PATCH /api/v1/orders/{orderId}/status` - Updates order state (PENDING -> PROCESSING -> SHIPPED -> DELIVERED).
- Auth Endpoints:
  * `POST /api/v1/auth/login` - Authenticates user & returns JWT token.
  * `POST /api/v1/auth/register` - Registers new customer account.

6.3 Client Migration Checklist & Logic Separation
--------------------------------------------------------------------------------
1. Replace `localStorage.setItem()` calls in controllers with `fetch()` / `axios` REST API calls.
2. Store JWT authentication token in `localStorage` or HttpOnly cookie.
3. Remove client-side distance matrix & stock reduction logic from `cart_controller.js`, deferring calculation to Spring Boot order placement service.
